# Page Depth & Architecture Standards

## Deep Architecture, Concise Sections

The Jurnii static site must feature a full, deep architecture. We do not use placeholder pages, empty card layouts, or shallow single-paragraph pages.

## No Scripted Copy Generation

Agents must not use scripts to generate commercial website copy.

Scripts may validate structure, links, headings, slugs, and ontology coverage. They may not generate H1s, page sections, card descriptions, CTA text, or page-specific narratives.

Website copy must be written directly from the brand guide and ontology by the agent, with page-specific reasoning.

> **Use scripts to check the site. Do not use scripts to think for the site.**

However, "deep" does not mean "essay-style text walls." The goal is structured, commercially rigorous depth. 

Every Detail Page (Feature, Solution, Use Case, Product) must follow this pattern:
- **6-10 distinct sections** answering core commercial questions.
- **Specific Cross-Linking:** Pages must link out to related products, features, solutions, and use cases.
- **Concise Copy within Sections:** Use an H2, 1-2 paragraphs (~250 characters max), followed by card grids, lists, or buttons. Do not write blog-style essays.

### Feature Page Requirements
Every Feature page must answer:
- What capability is this?
- Who uses it?
- What problem does it solve?
- What product or products does it belong to?
- What solution does it support?
- What use cases does it enable?
- What should the visitor do next?

### Solution Page Requirements
Every Solution page must answer:
- What business problem is this solving?
- Who owns this problem?
- What products support it?
- What features are involved?
- What use cases sit under it?
- What commercial result does it target?

### Use Case Page Requirements
Every Use Case page must answer:
- What situation is the customer in?
- What pain point are they trying to solve?
- Which persona cares?
- Which product helps?
- Which features are relevant?
- Which solution category does this belong to?
- What action should they take?

### Index Pages
Index pages (`features/index.html`, `solutions/index.html`, etc.) must fully list all available capabilities and link down into them. No orphans.

**Under no circumstances should the commercial ontology be collapsed to save time.** If the brand guide defines 10 features, 10 feature pages must be created.
