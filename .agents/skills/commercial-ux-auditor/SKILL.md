# Commercial UX Auditor

## When to use
Use when reviewing an existing page's clarity, conversion potential, buyer relevance, and commercial logic before executing a redesign.

## When not to use
Do not use for visual design (colour/typography) decisions or low-level HTML debugging.

## Required inputs
* Target page HTML/content
* ICP definitions and Brand Context

## Step-by-step instructions
1. **Identify the Audience:** Determine who the page is for (e.g., CPO, CCO, Operator).
2. **Evaluate the Problem:** Assess if the commercial problem is clarified immediately.
3. **Verify the Mechanism:** Check if the page clearly explains what Jurnii does about the problem.
4. **Validate Proof:** Ensure claims are supported by specific proof points (numbers, metrics) rather than consulting filler.
5. **Check the CTA:** Verify that the next step is specific (e.g., "Book a Demo") and visible without scrolling.

## Constraints
* Do not evaluate based on subjective "feel." Every finding must tie to a commercial outcome (NGR, churn, conversion).
* Do not use UX softness terms ("delightful", "seamless").

## Output format
For every issue found, output strictly in this format:
- **Finding:** [What is currently on the page]
- **Commercial consequence:** [Why this hurts conversion or credibility]
- **Recommended change:** [What to do instead]
- **Affected section/component:** [Specific HTML element or class]

## Examples where useful
* "Review the current index.html to see why it isn't converting CPOs."
* "Audit the 'Solutions' page before we redesign it."
